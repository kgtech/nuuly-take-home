# Decisions added during the V2 run

One line of reasoning each. Storage decisions are in `DESIGN-V2.md`; front-end ones in `frontend/DECISIONS.md`.

- [A1] Branches are `v2-<slug>`, not `v2/<slug>`: git cannot create `refs/heads/v2/...` while the branch `v2` exists (cannot lock ref), so PROMPT.md's naming is unworkable as written.
- [A2] `.fable/` is committed on `v2` as PROMPT.md requires; nothing is excluded through `.git/info/exclude`, so the run's record travels with the branch.
- [A3] (superseded by DESIGN-V2 §9) Redis calls fail soft through one `RedisGuard` (catch, WARN once per role per 10 s, return empty) instead of a circuit breaker library: the design already falls back to Postgres on every miss, so the only thing a breaker would add is a shorter wait, which the 250 ms command timeout already gives.
- [A4] (partly superseded by §9: Redis is gone; the group stays `readinessState,db`) The readiness health group is `readinessState,db` only: Redis down does not make the service unready because every endpoint keeps working (DESIGN-V2 §4); `/actuator/health` still reports the Redis component so an operator sees it.
- [A5] (superseded by §9) Cache versions come from `sku.version`, incremented in the same UPDATE as the quantity, rather than from ledger ids: the version is returned by the write that produced it, with no extra query, and a read populates with the row's own version.
- [A6] (superseded by §9) Writes refresh only existing cache entries (`onlyIfPresent`): a SKU nobody reads never occupies Redis memory, so "most used" is decided by reads alone.
- [A7] (superseded by §9) The Redis replay copy is written after commit (transaction synchronization), never inside the transaction: a rollback must not leave a response in Redis that Postgres never stored.
- [A8] (superseded by §9) Tests bind the Redis container to a fixed host port and run it with `--save "" --appendonly no`, matching compose: a real `docker restart` then keeps the address the app uses and comes back empty, which is what the durability test needs to show.
- [A9] (superseded by §9) The test cleanup (`Tables.reset`) truncates the tables and FLUSHALLs Redis in one call: a cached count must never outlive the rows it copies, and a helper that only truncated let stale counts leak between tests.
- [A10] (superseded by A33) The idempotency advice keeps Z1's shape (advisor + interceptor) but at READ COMMITTED with REQUIRES_NEW and no retry: a concurrent claim blocks on the primary key instead of raising 40001, so the retry machinery had nothing left to do.
- [A11] The append-only trigger raises SQLSTATE P0001 (plpgsql `RAISE EXCEPTION`) rather than a privilege error: the tests assert the state, and no role separation exists in this deployment to make 42501 truthful.
- [A13] (superseded by §9) The Redis replay copy stays (DESIGN-V2 §5 alt. 6): the brief asks Redis to take part in idempotency, and the copy answers replays and mismatches without Postgres; Postgres-only idempotency was the simpler alternative and is recorded as rejected for that reason, not for throughput.
- [A14] `quantity = SUM(quantity_delta)` is asserted by tests, not maintained by a trigger (DESIGN-V2 §5 alt. 7): the conditional UPDATE must stay the single statement that decides and returns the balance.
- [A15] (superseded by §9) 5 s stock TTL, 250 ms Redis timeout, 64 MB Redis memory: reasons in DESIGN-V2 §6 "Tuning values"; the TTL is the only one a deployment is expected to tune.
- [A16] (superseded by §9) Two clocks decide the 24 h key boundary (Postgres `now()`, app clock for the Redis copy); skew of s seconds moves the Redis answer by s seconds; accepted at this scope and stated in DESIGN-V2 §6.
- [A17] The Idempotency-Key stays a UUID (S3) although Stripe and the IETF draft accept any string: a `uuid` column is 16 bytes with no length or encoding attack surface, and the front end generates v4 UUIDs; the divergence is documented in the OpenAPI (`format: uuid`) and here. No `Idempotent-Replayed` response header is sent: the spec's clients don't read it and the contract's headers are limited to `Link`; recorded as a deliberate omission.
- [A18] A tombstoned idempotency row (response columns cleared by the README's clean-up) answers 400 "Invalid request" whatever its age: the key is used up, and a 500 would suggest a fault where an operator action happened.
- [A19] POST bodies above 4 KB (by Content-Length) are 400 "Invalid request" before parsing: the contract's body is `{"quantity":n}`; chunked bodies without a length are not capped (Jackson parses them; measured 40 MB in 0.65 s).
- [A12] CI (as written in `.fable/ci-workflow.yml`, see DEVIATIONS.md) runs on `ubuntu-latest` with Temurin 25 and Testcontainers against the runner's Docker; the front-end job runs `npm ci`, lint, typecheck, test and build in `frontend/` (it presumes the front end is present, which it is once PR #62 merges).
- [A20] The compose app is published on host port 18080 (`APP_PORT` overrides) and the front end's dev server on 15173 with API target 18080: the defaults 8080 and 5173 are frequently taken on a developer machine, and a test run must not depend on them (owner request).
- [A21] v2 is a path version (`/v2/inventory`), additive to the frozen four operations: DESIGN-V2 §8 "Why a `/v2` path"; header or query versioning rejected as invisible, extending v1 rejected as a contract change.
- [A22] Details live in `sku_details`, not on `sku`: the stock UPDATE rewrites the whole row under its lock, and a wide row taxes every purchase for text it never reads (§8 "Schema").
- [A23] POST /v2 on an existing SKU is 409 with a body that names the two operations to use instead; upsert rejected as a lost update and a double initial-stock on an unkeyed retry (§8 "Create").
- [A24] PUT is full replacement with an optional strong `If-Match`; mismatch is 412; PATCH (merge or JSON Patch) rejected for null ambiguity and a second grammar; mandatory `If-Match` rejected as a tax on scripts (§8 "Edit").
- [A25] v2 errors are text/plain fixed texts like v1 (one helper, one front-end path); RFC 9457 rejected as a second grammar for four situations (§8 "Errors").
- [A26] Cost is `{amount: int64 minor units, currency: ^[A-Z]{3}$}` or null; decimal strings and floats rejected; the ISO 4217 list is not checked (§8 "Representation").
- [A27] v2 reads are one join at READ COMMITTED and never use or fill the Redis stock cache; the spec's GET keeps the hot path (§8 "Reads").
- [A28] `POST /v2` answers 201 (a create that only creates), not v1's 200 for create-or-update; the idempotency store accepts 201 and 409 for `'create'` rows.
- [A29] (superseded by A33; the canonical create form and the v1 hash bytes stay) The `@Idempotent` contract is widened from `(String, int, String)` to `(String, int | Fingerprinted, String)`: the v1 fingerprint bytes are unchanged (`op\nskuId\nquantity`), and a create request renders its own canonical form as length-prefixed fields after `create\nskuId\n` (§8 "Create"; Y3 kept: never the raw body).
- [A30] Redis is removed (owner decision on PR #74, DESIGN-V2 §9): the invariants were enforced in Postgres all along (§4), so the cache and the replay copy were complexity with no correctness benefit in this scenario; a read is one primary-key lookup that never waits on a writer.
- [A31] The count cache design (§3: versioned refresh, TTL as the staleness bound, populate on read only) is kept in the document and the history as the design to bring back for a read storm on a few SKUs, not deleted.
- [A32] Post-commit synchronization (`AfterCommit`) goes with the cache: nothing runs after commit any more, so a crash after commit leaves no second write to worry about (§4 "crash between the Postgres commit and the Redis refresh" no longer exists).
- [A33] Idempotency-Key handling is an explicit call, not advice (issue #81; supersedes Z1, A10 and A29; DESIGN-V2 §10): `InventoryService.add`, `purchase` and `create` pass the write to `IdempotencyStore.run(key, operation, skuId, canonicalRequest, write)`, which opens a READ COMMITTED transaction (`PROPAGATION_REQUIRED`), or joins a READ COMMITTED or DEFAULT caller's transaction and refuses any other isolation (`IllegalStateException`); when joined, the caller's `now()` (T1) and rollback scope apply. Z1's advisor existed to sit between `@Retryable` and a SERIALIZABLE transaction; with both gone (§7) it only added a pointcut, arguments read by position, a per-method generic strategy and a `REQUIRES_NEW` that would suspend a caller's transaction. The canonical request stays the quantity's digits on the spec POSTs (the Y3 bytes, so stored keys still replay) and `CreateSku.fingerprint()` on the create; the web layer renders the stored response through the domain's `KeyedResponses` interface, so the domain names no HTTP type (Z2).
- [A34] Order on every keyed POST (refines U3, S2, S3; issue #81): body validation (controller) → Idempotency-Key format → skuId pattern → claim and write. The key and skuId checks run once each, in the service, before any I/O, and neither answer is stored. Each service method names its own answer for a malformed skuId (create 400, purchase 404), so the domain's skuId check no longer switches on `idempotency.Operation`.
- [A37] App-wide HTTP code lives in `com.kgtech.inventoryapi.web`, not in the feature's web layer (refines D10, Z2, S5, S6, C1, C2; layout review, owner request 2026-09-29). The error advice, the Tomcat valve, the container customizer and `DispatcherServlet` override and the Jackson configuration serve every path (G10, S6, C1), so they move out of `inventory.web`: `InventoryErrorAdvice` (name kept, so the tests and log lines that match its simple name are unchanged; its logger category moves with the package, from `com.kgtech.inventoryapi.inventory.web.InventoryErrorAdvice` to `com.kgtech.inventoryapi.web.InventoryErrorAdvice`), `TextErrors` (moved whole rather than split into generic and feature halves, so S5 keeps one helper), `TextErrorReportValve`, `ServletContainerConfiguration`, `StrictStringsConfiguration` and `BodyTooLargeException`. The API-wide `@OpenAPIDefinition`, with its title and version, moves off `InventoryController` to a package-private `web.OpenApiConfiguration`: v2's `SkuDetailsController` is a second controller it also describes. `web` depends on no feature package; its public types are `HttpConstants`, `TextErrors` and `BodyTooLargeException` (thrown by `inventory.web.CappedBodyRequest`), and only the members `inventory.web` uses are public. `inventory.web` keeps the feature's endpoints and filters, all package-private, and gains `Paging`, the one helper for the next-page Link (C2) and the repeated-`after` check (Z3) that both list endpoints carried. Members follow D10's visibility rule too: `Operation.dbValue()` is package-private and the `SkuDetails` and `SkuCost` limits are private. `idempotency` is the inventory feature's Idempotency-Key support, not a generic facility (its operations, skuId and request hash are inventory's), though it imports no inventory type.
- [A38] Each write returns a result of its own outcome family (refines R1, U1 and A33): `sealed interface WriteResult<O>` with `Done<O>(O outcome)`, `Stored<O>(StoredResponse response)` and `InvalidRequest<O>()`. `add` returns `WriteResult<StockOutcome.Add>`, `purchase` `WriteResult<StockOutcome.Purchase>` and the v2 create `WriteResult<DetailsOutcome>`; purchase's 404 for a malformed skuId is `Done(NotFound)`. `StockOutcome` and `DetailsOutcome` no longer extend `WriteResult`, so each controller's switch is exhaustive over its own operation's outcomes and the three `throw new IllegalStateException("not a ...")` branches for impossible outcomes are gone. `KeyedResponses` renders each family through its own typed `toStored` (`StockOutcome`, `DetailsOutcome`), and the service passes the operation's renderer to `IdempotencyStore.run`, whose signature is unchanged. `InventoryPage` and `SkuPage` become one `Page<T>(List<T> items, Optional<Next> next)`, and `list` and `listSkus` share one keyset routine. No status, header, Content-Type, body or stored replay changes, and `openapi.yaml` is byte-identical (the page types are never serialized).
- [A39] ArchUnit guards the package layout beside `PackageBoundaryTest` (dependency approved by the owner 2026-09-29): `com.tngtech.archunit:archunit`, the core artifact rather than archunit-junit5, ArchUnit 1.5.x (built with 1.5.1), versioned only in `gradle/libs.versions.toml` (S10; it is not in the Spring Boot BOM). One `ArchitectureTest` in the root test package runs plain JUnit `@Test` methods that call `rule.check` on the imported main classes: no package cycles, dependency direction (web and idempotency know no feature; the domain knows no web layer, HTTP, servlet or Tomcat type), where app-wide HTTP classes and every `@Configuration` live, package-private controllers, repositories and `inventory.web` types, `JdbcClient` only in the repositories and `IdempotencyStore`, the exact public types of `web`, `idempotency` and `inventory`, `web`'s public constants as an explicit list (javac inlines them, so no bytecode reader shows), and A38's result and page types. Rules keep ArchUnit's default of failing when they match nothing, so none passes vacuously. javac inlines constants and bytecode keeps no string literals, so `PackageBoundaryTest` keeps the source scans, now recursive: the `Idempotency-Key` literal only in `HttpConstants`, header-name constants in tests, no transport imports in the domain or `idempotency`, and no `com.kgtech.inventoryapi.inventory.` in `web` or `idempotency` sources (a constant-only import leaves no bytecode edge).
