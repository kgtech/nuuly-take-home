# Lessons from the first build (Opus run, main at 317ab0c)

What the retrospective of the first build found, rewritten as instructions. Each line ends with its evidence count and the retro ID it comes from (K = practice that worked, R = open finding, S = spec gap, T = tooling, D = an owner decision that cost rework). Counts are exact: "3 of 9 runs" means three of the nine issue-pipeline runs (#1–#8, #15). Pointers name files, PRs and logs on `main` or under `.orchestrator/` that you can read.

## Process

1. Run a preflight before any work: base branch on the remote, push access, `docker info` and the socket Testcontainers resolves, the JDK toolchain, free host ports, a clean tree. One Docker-socket stop in run #1, then 0 in the next 10 runs (K-01).
2. Give every worker the absolute worktree path, the branch and the plan path; create the branch yourself before handing off. Hook blocks fell from 2 of 3 runs to 0 of 6 once the handoff carried the path (K-02).
3. Let one role own the tests. In the first build 0 of 37 implementer, fixer and orchestrator commits touched `src/test`, and 17 of 20 test requests were filled in one cycle (K-03).
4. When a test or plan looks wrong, stop and propose instead of working around it. Four wrong plans (#2 55P03, #7 URI helper, #21 reason phrase, #6 Z1 contradiction) were each cleared in one cycle (K-04).
5. Before changing a generated decision file, reproduce the committed output byte for byte first. 10 of 10 reproductions matched and `DECISIONS.md`/`CLAUDE.md` never drifted across 9 board changes (K-05). Never hand-edit `DECISIONS.md` or `CLAUDE.md` (D: the one hand edit in #1 produced finding R1-6 and a regeneration, e7238f3).
6. Reply to a declined finding with a fixed phrase ("Owner decision: not changed in this PR.") and leave the thread open; 0 declined findings were re-raised (K-06).
7. In round 2, check the round-1 fix commits for regressions: 3 of 4 round-2 findings were regressions introduced by round-1 fixes (K-07).
8. Save one prompt file per invocation: 55 files from #6 on, 0 in #1–#5; every handoff problem could be checked word for word only where the file existed (K-08). Log an ISO timestamp for every step and gate; no run logged one, so about 10 h of elapsed time cannot be split between waiting and work (R-06, every run).
9. Gate on the plan before code: 8 overrides at 4 of 9 plan gates cost 0 rework commits, while changes made after the verifier cost 1–8 commits each (K-10).
10. Record a decision change as a five-field comment (What / Was / Now / Why / Affects) on the issue and never edit the issue body: 14 comments in the first build, 19 on `main` now, 0 body edits after the rule (K-11). Read them in `issues.md` under "Current decision".
11. Make the verifier list every unaddressed round-2 finding: before the rule one was lost (#12 F3), after it 2 of 2 surfaced (K-12). Send round-2 MINOR and NIT findings to a fixer too; 3 of 4 round-2 findings got no fixer and 2 of 2 were fixed only after the owner asked (R-09).
12. "No preference" and silence are not approval; ask again. Silence was recorded as approval 3 times and 9 re-asks were needed in 5 of 11 runs (K-13, R-13). Make each question self-contained: one decision, the text quoted inline, IDs explained.
13. Critique the finished build with several lenses, a reproducing verifier and mutation testing: 39 findings, 36 confirmed, 38 accepted; the per-PR reviews had raised 0 of the 12 test-economy findings (K-09, R-03). Add a test-economy check to every PR review: tests differing only in input, the same behaviour tested at two layers, tests that cannot fail.
14. Don't start a critique while a story is open: the open-issue gate stopped one attempt at 457f3ab before it reviewed a baseline that lacked #8 (K-14, 1 of 2 critique starts).
15. Check an agent's claims before acting on them: a false open question was withdrawn, a "161 vs 64" miscount and the 55P03 translation were caught by reading the source (K-15, 3 cases).
16. Give reviewers a channel for "the plan or a decision is wrong" and put every such note to the decision maker before the fix round. 3 plan-wrong notes in 2 of 9 runs went nowhere, and 5 of 5 critique decision challenges had never been raised in a PR review; one became the only MAJOR defect (C-01) (R-01).
17. Surface every concern an agent returns but does not act on, or hand it to the next agent. At least 7 items in 5 runs were logged and dropped; two of them came back as issue #15 (R-04).
18. Commit the session record (agent-prompts entry) on the branch before the final summary, and discard a stale draft whose content is already on `main`. The approval gate changed nothing (6 of 6 approved unchanged), held PR #18 about 4 h, and one stale draft was re-reported in 6 run logs (R-05).
19. Every pushed commit must build and pass on its own, apart from the first failing-tests commit. 4 red commits in 3 runs (b68f4fd, 3724d94, fad00c8, 0beba0f) came from one agent committing on top of another's uncommitted work (R-07).
20. Review replies give a verdict and a SHA or evidence, never the pipeline story ("filed as a test request", "the test author owns tests"): at least 20 such replies on 5 of 9 PRs (R-08).
21. Give one role the job of resolving threads fixed after round 2; 2 threads on PR #19 stayed open although fixed, and 1 on PR #11 was resolved with no reply (R-11).
22. Allow scratch space under `$TMPDIR` for smoke checks and delete it before returning; a flat "no scratch files" rule was relaxed silently in 4 runs plus the critique (R-14).
23. When a decision challenge from a critique is approved, post its decision-change comment on the fix issue when that issue is created: 3 were promised in triage and 0 posted (R-15).
24. Treat a narrower reading of a rule as a decision change (1 case: S1 read as "stock writes only" in #6, R-16). In mutation-based test pruning, judge uniqueness per PIT scope: a test that is the only killer of a mutant in any scope stays (1 case, C-29; R-17).
25. Decide first, check after cost rework in 4 of 9 runs (#1, #6, #7, #8): every post-verifier change in the retro's cost table was one. Where the owner asked first (#7 OQ2, #7 R1-2), nothing needed rework (D, DB-08).

## Design pitfalls

26. Verify every framework or runtime claim before planning on it, and mark unverified claims as open questions or as the first tests to write. Planners passed unchecked claims down in 6 of 9 runs; each was later disproved (R-02): 55P03 arrives as `UncategorizedSQLException`, not `PessimisticLockingFailureException` (#2, `.orchestrator/issue-2-log.md`); a filter matched the raw URI (#3 MAJOR); `@Repository` translation rewrapped the documented exception (#6); the 505 reason phrase is "HTTP Version not supported" (#21).
27. Two of two unsourced library claims from the design phase were wrong (Hibernate 7.1 vs the BOM's 7.4.5; 55P03 translation). A claim marked unverified with a proving test (`ai/research-sources.md:62`, Tomcat and `%2F`) was never carried into a story and surfaced twice as a MAJOR (PR #18 R1-1, critique C-01). Carry every unverified design claim into a story with its test (S-01).
28. Tomcat rejects an encoded slash, a malformed or invalid-UTF-8 percent-escape, `%00`, an oversized request line and a missing Host before Spring runs, and answers with its own HTML page. Any text/plain error contract needs a Tomcat-level error valve and a decision on `%2F` (`encodedSolidusHandling`). See decision C1 in `DECISIONS.md`, `TextErrorReportValve.java`, `ServletContainerConfiguration.java` and `TomcatRejectionIntegrationTest.java` (PR #31); MockMvc never sees these requests, so test them through a real server (C-01, 1 MAJOR).
29. A global `@RestControllerAdvice` rewrites `/actuator/**` and springdoc errors too. Decide the scope explicitly (S6, C1) and test the library paths with a real server (`LibraryPathErrorsIntegrationTest.java`). Z3's 400 mapping for an undecodable query was the secondary cause (C-06; D: the #7 Z3 override cost 4 invocations and led to #21).
30. Spring's `@PathVariable` strips `;matrix` content, so `POST /inventory/ABC-1;lot=7` wrote to `ABC-1`; and `@Transactional(readOnly = true)` borrows a connection before any argument check, so an invalid ID waited 30 s with the database down. Bind the raw path segment and validate before opening a transaction (C-04, C-05; issue #23, PR #34 open).
31. Spring's `produces` condition ignores `q=0`, so `Accept: application/json;q=0` still wrote stock (C-34; issue #23).
32. A claim-first idempotency row (`INSERT … ON CONFLICT DO NOTHING RETURNING`) cannot have NOT NULL response columns; make them nullable with an all-or-none CHECK and set them in the same transaction (Y4 vs R2, caught at the #6 plan gate; S-05, K-10). Store `content_type` with status and body so a replayed 200 is JSON and a replayed error is text/plain (Y4).
33. Under SERIALIZABLE, a `SUM(...)` predicate takes SSI locks that make writers on unrelated SKUs abort each other (0.1–0.5 retries per request at 10–16 clients on a small ledger; 0 exhausted). Test cross-SKU concurrency, not only same-SKU (C-03; issue #26 open).
34. An unbounded list endpoint is a memory bomb once anyone can create SKUs: 8 concurrent unpaged `GET /inventory` over 1,000,000 SKUs returned 500 with `OutOfMemoryError`. Default to a page size and a `Link: rel="next"` (C-02, decision C2, PR #33).
35. Build the next-page `Link` from the routed path, never from the raw request URI, or `/%69nventory` yields `/%2569nventory` (C-08, PR #33).
36. Don't write an acceptance criterion that contradicts another rule: AC3 "versions only in the catalog" conflicted with S10's docs rule and the image tags story 5 needed; it drove 5 of #1's 12 findings, was reworded and then deleted after the verifier, and S10 has had no automated check since (S-03; D).
37. A new rule can contradict the design it was written for: Z1's first wording did, costing 1 stop and a second comment (S-04). 11 of 14 decision changes surfaced after plan approval (S-02); expect them and route them through the board.
38. Store operator-visible rules in Postgres, not convention: nothing stopped `UPDATE inventory_ledger` (C-10), the idempotency table grows without bound and T1 makes a purge unsafe (C-16), and Postgres was published on 0.0.0.0 with a committed password (C-12). Issues #24, #25, #27 (open).
39. A test that checks a hand-written copy of a query proves nothing about the shipped query (C-15, `LedgerQueryPlanTest`); pin boundaries at both sides (24h + 1 s and 24h − 1 min, C-14); assert that a concurrency test's interesting branch actually ran (C-31).
40. No CI workflow existed through 317ab0c: 0 of 13 merged PRs had checks and every "green" was a local run (S-06). Add CI before the first PR.

## Tooling fixes

41. GitHub: the same account cannot approve its own PR, so post reviews as comments: `gh api repos/<o>/<r>/pulls/<n>/reviews -f event=COMMENT` with inline comments (`commit_id`, `path`, `line`, `side`); resolve threads with the GraphQL `resolveReviewThread` mutation. Every review in the first build is COMMENTED (run-index part 2 §2).
42. GitHub returns 422 "User can only have one pending review per pull request" when the account already has a PENDING review on the PR. Check `gh api repos/<o>/<r>/pulls/<n>/reviews` for state PENDING before posting; if a post is rejected, keep the full text and stop. 1 occurrence (PR #14, review 5318430555) cost issue #15 / PR #16 and let C-17 escape (R-12, `.orchestrator/issue-6-log.md`).
43. GitHub closes issues from "Closes #n" only when the PR merges into the default branch. When your PR base is another branch, close each issue yourself (`gh issue close <n> --comment "Closed by #<pr>"`). (Rule from `PROMPT.md`; all first-build PRs targeted `main`, so it was not exercised there.)
44. Share one Postgres Testcontainer across every Spring context and cut the number of contexts. At 317ab0c the suite starts 6 `postgres:18` containers and 7 Spring contexts for 788 tests in about 28 s; the critique measured 24.1–24.8 s → 15.1–16.1 s wall with one static container (`@Bean(destroyMethod = "") @ServiceConnection`), and one meta-annotation for the Boot tests. Class-level `@MockitoBean`/`@MockitoSpyBean` splits the context cache (C-20, C-21, C-22, C-30; issue #29 open; `src/test/java/com/kgtech/inventoryapi/TestcontainersConfiguration.java`; PR #20 body).
45. Don't repeat the same validation matrix at every layer: the skuId regex ran in about 120 cases across 6 classes and the key format at 5 layers; PIT showed the removed rows killed 0 unique mutants (C-23–C-28; issue #30 open).
46. OrbStack Docker: Testcontainers could not find the socket (`/var/run/docker.sock` pointed at a missing Docker Desktop socket). Fix: symlink `/var/run/docker.sock` to `~/.orbstack/run/docker.sock` and delete the `docker.client.strategy` line from `~/.testcontainers.properties` (1 stop, `.orchestrator/issue-1-log.md` lines 25–30). Run tests through Gradle: `TestcontainersConfiguration` reads the image from the `inventory.test.postgres-image` system property.
47. Port 8080 may be held by another container (`season-draft-web` in the first build). Decide once what agents may do (stop and restart it, or use a fallback port) and write it down; the same question was asked in 3 of 3 runs where the port was held (R-10).
48. The auto-mode permission classifier denied `docker stop` (2 of 2 attempts in #7, allowed in 3 other runs) and `resolveReviewThread` (5 threads left open on PR #18). After a denial, never re-issue the command to another agent; ask a person or take another route (T-01, R-10).
49. `ai/export-board.mjs` imports an unpinned `playwright`; 4 of 4 runs from #6 on needed a scratch install and `PW_EXE`, and #8's first try failed on a browser version mismatch. Pin the Playwright version (and browser) before using the exporter (T-02).
50. GitHub returned 502 on one review POST although the review had been created; check what exists before retrying (T-04, `.orchestrator/critique-log.md` line 2692).
51. Run mutation testing as a throwaway Gradle edit (`info.solidsoft.pitest` 1.19.0, PIT 1.30.0, JUnit 5 plugin 1.2.3; `fullMutationMatrix`, XML output) scoped to the classes under review; commands and scores are in `.orchestrator/critique-report.md` lines 11–47. Reruns showed 109/126 (no-DB) and 119/125 (Testcontainers) at 317ab0c (`.orchestrator/results/issue-23-step3.md`).
52. A `git stash` stack is shared across worktrees; prefer a WIP commit. Keep orchestration files (`.orchestrator/`) out of the repo with `.git/info/exclude` (`.orchestrator/issue-1-log.md` line 4).
