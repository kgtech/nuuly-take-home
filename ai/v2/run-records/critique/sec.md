# Critique — sec (Security and operations) — v2 @ d01852a (reviewer report)

## Findings (all MINOR)
- F-sec-01 — Heap policy is only in compose.override.yaml (JAVA_TOOL_OPTIONS), not in the runtime image; #58 AC3 and README say the image sets it. Fix: `ENV JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75.0` in the Dockerfile runtime stage.
- F-sec-02 — `/actuator/health` has show-details never, so it names no component (README says it "shows the Redis component"), and it goes 503 while the service works; a probe on it would evict a working instance. Fix: `management.endpoint.health.show-components=always` and document that probes use /readiness, or fix the README sentence.
- F-sec-03 — No bound on JSON body size (Tomcat maxPostSize is for forms; Jackson bounds tokens not documents): a hundreds-of-MB `{"quantity":1,"x":[0,0,...]}` is parsed to completion on the request thread; 8 in parallel hold all workers. Repro: generate big.json and POST it; expected fast 400/413, actual 200 after seconds. Fix: Content-Length limit on the two POST paths (400 "Invalid request") or StreamReadConstraints.maxDocumentLength.
- F-sec-04 — Postgres growth undocumented: ledger grows forever (DELETE forbidden), idempotency_keys grows per keyed request incl. 404s from unauthenticated clients; the README's reclaim UPDATE has no index on created_at (sequential scan); no row-size/growth numbers; ledger retention unstated.
- F-sec-05 — Redis content is trusted verbatim for replayed responses (status/ct/body) and cached counts; no AUTH; a host-local writer can inject a response or pin a count for one TTL. Not remote; undocumented trust boundary. Mitigation: validate replayed ct ∈ {application/json, text/plain} and status ∈ {200,400,404}; document Redis must be private/AUTH'd.
- F-sec-06 — No CI runs (workflow inert under .fable/); already in DEVIATIONS.md; recorded, not missed.

## Checked and found met
Parameterised SQL everywhere; Lua values via KEYS/ARGV with validated key material; skuId ≤ 64 before I/O and varchar(64); quantity range and coercion; Tomcat header/line limits → text/plain; logging free of bodies/keys/skuIds at INFO/WARN, rate-limited Redis WARN; fixed error texts, no HTML/stack leaks; stores on loopback random ports (asserted); non-root multi-stage image, healthcheck, depends_on; actuator health only with probe groups, readiness = readinessState,db; Redis as a bounded LFU cache without persistence, 250 ms timeouts, every call guarded; after-commit-only cache writes; front end without innerHTML/eval; README run instructions and failure table.
